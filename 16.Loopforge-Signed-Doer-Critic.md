# 16.Loopforge-Signed-Doer-Critic

>

## Usage

# Loopforge — signed doer/critic pattern

Every substantive change follows: **sign → act → critic-verify → sign**. The
graph at `loopforge/graph/decisions.jsonl` is the source of truth for who did
what, whether artifacts drifted, and how to backtrack.

## When to use

- Any delegated implementation or edit task in the bound workspace (zcode_run or native).
- Any verification/review where the result should be auditable later.
- The user asks "why was X changed" -> `backtrack.sh`, don't guess.

## The ritual

1. **Before the doer runs** — record the plan (and expected hash if file exists):
   ```bash
   /Users/kirkwon/.openclaw-autoclaw/workspace/loopforge/bin/sign.sh <agent> coordinator plan "<target-file>" "what will be done"
   EXPECTED=$(shasum -a 256 <target-file> | awk '{print $1}')
   ```
2. **Doer acts** (zcode_run / herdr pane / native edit), then:
   ```bash
   /Users/kirkwon/.openclaw-autoclaw/workspace/loopforge/bin/sign.sh <doer-agent> doer implement "<artifact>" "summary"
   ```
3. **Independent critic** — never trust doer self-report:
   ```bash
   /Users/kirkwon/.openclaw-autoclaw/workspace/loopforge/bin/critic.sh <artifact> <expected-sha256> <self-contained-test-cmd>
   ```
   - Test command MUST be self-contained (reference only the artifact itself;
     e.g. `bash script script` not `bash script README.md`) — the critic sandbox
     mirrors only the artifact (d0004 lesson).
   - On FAIL_TEST, first check whether the test was badly designed before
     blaming the artifact; sign the diagnosis either way.
4. **Close the loop:**
   ```bash
   /Users/kirkwon/.openclaw-autoclaw/workspace/loopforge/bin/sign.sh critic critic verify "loopforge/artifacts/<name>.verdict.json" "PASS/FAIL + evidence"
   /Users/kirkwon/.openclaw-autoclaw/workspace/loopforge/bin/verify.sh          # chain must be intact before claiming done
   ```

## Rules

- Sign every decision, including failures and diagnoses — a FAIL node is more
  valuable than a silent retry.
- Roles: doer writes; critic NEVER writes (except its verdict file);
  coordinator signs plans/diagnoses and never upgrades FAIL to PASS by editing history.
- Never edit `decisions.jsonl` by hand; append only via `sign.sh`.
- `verify.sh` non-zero = do not claim completion.
- Backtrack: `/Users/kirkwon/.openclaw-autoclaw/workspace/loopforge/bin/backtrack.sh <id|--latest>` shows chronology + artifact drift.

## Hermes usage

| Delegation step | Loopforge step |
|---|---|
| Pre-delegate plan | `sign.sh <agent> coordinator plan` |
| zcode_run / doer executes | `sign.sh <agent> doer implement` |
| Independent verification | `critic.sh` (not doer self-report) |
| Final answer | `verify.sh` + `backtrack.sh --latest` as evidence |
