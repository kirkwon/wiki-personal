# Building Effective AI Agents - Anthropic Engineering (Schluntz & Zhang, Dec 2024)

**Source**: https://www.anthropic.com/engineering/building-effective-agents
**Date**: 2024-12-20
**Authors**: Erik Schluntz, Barry Zhang (Anthropic)

## Core Concept

Anthropic distinguishes between **workflows** (pre-defined LLM orchestration patterns) and **agents** (LLMs that dynamically direct their own processes).

## The Five Workflow Patterns

### Prompt Chaining
Decomposes task into sequence of LLM calls, each processing output of previous. Add programmatic checks (gates) on intermediate steps.

**Best for**: Tasks that can be easily decomposed into fixed subtasks. Trade latency for higher accuracy.
**Example**: Generate document → translate to separate language

### Routing
Classifies input and directs to specialized followup task. Separation of concerns.

**Best for**: Complex tasks with distinct input categories requiring different handling.
**Example**: Easy tasks → Haiku, Hard tasks → Sonnet

### Parallelization
Task broken into independent subtasks run in parallel, or processed by voting mechanism.

**Best for**: When subtasks can be parallelized for speed OR multiple perspectives needed for confidence.
**Variations**: Independent subtasks, Voting/ensemble

### Orchestrator-Workers
Central LLM dynamically breaks down tasks, delegates to worker LLMs, synthesizes results.

**Best for**: Complex tasks where subtasks can't be predicted (e.g., coding - number/files of changes unknown).
**Key Advantage**: Flexibility - subtasks determined by orchestrator based on input

### Evaluator-Optimizer
One LLM generates response, another provides evaluation/feedback in loop.

**Best for**: When clear evaluation criteria exist and iterative refinement provides measurable value.

## Core Principles

- Start with simple prompts, optimize with comprehensive evaluation, add complexity only when demonstrably improves outcomes
- Frameworks can help get started but reduce abstraction layers for production
- Agents ideal for open-ended problems where step count unpredictable, can't hardcode fixed path
- Agent autonomy = higher costs + compounding errors → need sandbox testing + guardrails
- Critical: agents must gain 'ground truth from environment at each step' to assess progress

## Agent Definition

- **Workflow**: Pre-defined orchestration patterns (chaining, routing, etc.)
- **Agent**: LLMs that dynamically direct their own processes and tool usage
- **Key Distinction**: Workflows = predictable patterns, Agents = adaptive, environment-driven

## Implementation Advice

- Begin with command/interactive discussion with human to clarify task
- During execution: gain ground truth from environment at each step (tool results, code execution)
- Can pause for human feedback at checkpoints or when encountering blockers
- Task terminates on completion or stopping conditions (max iterations)
- Design toolsets and documentation clearly and thoughtfully
