# Dojo Self-Healing v2 — Complete Implementation

## Summary

Transformed the Dojo from an "honest diagnostician" (Phase A/B fix from earlier today) into a **resource-aware self-healing system** with a 5-phase architecture. The system now monitors, classifies fixes by effort, auto-executes safe fixes, and generates plans with prior-art gathering for complex fixes.

**Implemented:** 2026-07-19, 5 phases, all independently verified.

## Architecture (Post-v2)

```
Sessions → dojo-eval.py (monitor) → dojo-analyze.py (classifier)
                                          ↓
                                    fix_plan.json
                                          ↓
                                    fix-router.py ←── NEW (Phase 2)
                                   /      |       \
                              Easy      Medium    Complex
                                ↓         ↓          ↓
                          Auto-exec   Recommend   Gather resources
                          + SHA256    + config    → Generate plan
                          + log                   → Queue
                                ↓                    ↓
                          circuit-breaker.py   ~/clawd/.hermes/plans/
                         (Phase 1 + 3 fix)         (Phase 2)

         outer_loop_dojo_eval.py (Phase 4)
         ────────────────────────────────
         detect_stagnation() → LOG ONLY (apply_fix disabled)
```

## Phase Results

### Phase 1: Circuit Breaker last_success Bug ✅
- **Bug:** All 16 circuits had `last_success: null` — monitor never tracked healthy tools
- **Fix:** Added `healthy_tools` to `dojo-eval.py` output; added success-recording loop to `circuit-breaker.py`
- **Result:** 10/25 circuits now have `last_success` populated
- **Files:** `dojo-eval.py` (+11 lines), `circuit-breaker.py` (+14 lines)

### Phase 2: Effort Router (fix-router.py) ✅
- **New script:** `~/.hermes/scripts/fix-router.py` (500 lines)
- **Classification:** Easy (auto-exec) / Medium (recommend) / Complex (plan + queue)
- **Resource gathering:** Searches disk (skills), learned_patterns.json, circuit-breaker state
- **Live run:** 9 plans queued, 1 recommended, 0 spam introduced
- **Output artifacts:** fix-router-log.jsonl, fix-queue.json, 9 plan files

### Phase 3: Circuit Breaker Enforcement ✅
- **Blocked-tool warnings:** Phase 5/5 block in `dojo-eval.sh` lists open/half-open tools
- **blocked-tools.json:** Written for downstream processes
- **Auto-reset:** Healthy tools with open/half-open circuits force-reset
- **Full cycle test:** open (4 fails) → feed healthy monitor → closed with last_success

### Phase 4: Outer Loop Safety Gate ✅
- **Hazard found:** `outer_loop_dojo_eval.py:apply_fix()` mixed Python/bash syntax, would corrupt `dojo-eval.sh`
- **Fix:** Disabled `apply_fix()` — now logs stagnation events only, no file writes
- **Design decision:** DISABLE > REWIRE because fix-router already handles fixes properly

### Phase 5: Documentation + gbrain ✅
- This page, cross-linked to prior audit findings and self-healing concept page
- Phase logs in `~/clawd/28.Dojo-SelfHealing-v2/logs/`
- Project README with architecture diagram

## Key Design Principles

1. **Honest diagnostician > dishonest surgeon** — don't fake fixes
2. **Effort-scored routing** — easy=auto, medium=recommend, complex=plan+queue
3. **Resource gathering before planning** — search disk, patterns, breaker state for prior art
4. **Auto-reset healthy tools** — if a tool is clean in current period, close its breaker
5. **Disable > rewire dangerous code** — the outer loop's stagnation alert is valuable, its auto-patch was not
