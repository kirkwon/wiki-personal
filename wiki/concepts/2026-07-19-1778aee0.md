# Dojo Auto-Heal System — Audit Findings

**Date:** 2026-07-19
**Auditor principle:** "My processes might be lying to me" — every claim verified through independent code paths, not script self-reports.
**Status:** Phase A + B complete. Further work planned.

## TL;DR

The Dojo auto-heal pipeline (`dojo-eval.sh`, cron `a49cd7f6f722`) was producing **fake auto-fixes**. It claimed to add retry/timeout handling to skills but only appended comment graffiti to SKILL.md files — zero lines of functional code. 71 duplicate spam lines had accumulated across 11 files. After audit + fix, the system is now an **honest diagnostician, not a surgeon**: it reports what's broken, but won't fix it for you.

## System Architecture

```
dojo-eval.py (monitor)     → scans session DB for tool failures
dojo-analyze.py (analyzer) → classifies failures, generates recommendations
dojo-eval.sh (auto-heal)   → applies fixes via apply_fix() function
circuit-breaker.py          → tracks tool success/failure over time
outer_loop_dojo_eval.py     → 15-min loop, can patch dojo-eval.sh itself
```

**Cron schedule:** Daily (`a49cd7f6f722`), `no_agent: true`.

## What Was Broken (5 Findings)

### 1. Fake Auto-Fixes (Fixed — Phase B)
The `apply_fix()` function in `dojo-eval.sh` had two actions (`increase_timeout`, `add_retry_handling`) that appended comment lines like `# Auto-updated: add proper retry/backoff handling` to SKILL.md files, then printed "Added retry handling note to SKILL.md." This looked like a fix but changed no functional behavior.

**Fix:** Replaced with honest `⚠️ MANUAL ACTION required` messages pointing to `latest_analysis.json`.

### 2. No Idempotency (Fixed — Phase A)
Every cron run re-appended the same comment. No grep-before-append guard. Result: `plan` skill had 8 copies, `arxiv` had 10 copies of the same comment.

**Fix:** Added `grep -q` guards to all `>> SKILL.md` append sites.

### 3. Two Hidden Auto-Heal Patterns (Fixed — Phase A)
Cleanup initially found 45 lines matching `dojo-auto-heal` (with non-breaking hyphen `\u2011`). Audit discovered a second pattern: `# Auto-patched:` from a July 13 agent session (`20260713_104113_84f864`) that had its own `apply_fix` implementation. 6 additional lines cleaned.

### 4. Circuit Breakers Never Record Success (Open — Separate Bug)
All 15 circuit breakers show `last_success: null` — zero successes ever recorded. Breakers stay half-open forever. Root cause in `dojo-eval.py` monitoring layer (not the auto-fix layer). **Not yet fixed.**

### 5. Outer Loop Self-Patching (Known Risk — Not Touched)
`outer_loop_dojo_eval.py` (runs every 15 min) has its own `apply_fix` that patches `dojo-eval.sh` by wrapping the analyze call in a retry loop. Crude text replacement with only `bash -n` validation. **Not modified.**

## Verification Methodology

Applied the "my processes might be lying to me" principle with 5 independent checks per phase:

| Check | Method | Proves |
|-------|--------|--------|
| Independent grep | Separate Python code, broader patterns | Cleanup actually worked |
| SHA256 hash comparison | Baseline vs post-fix | Files genuinely changed |
| Structural analysis | Count unguarded `>>` appends | Guards correctly placed |
| Functional simulation | Run patched function with test inputs | Correct runtime behavior |
| Regression test | Spam count before/after simulation | Fix cannot reintroduce spam |

**Key lesson:** The cleanup script self-reported "8 files cleaned" but missed 3 files with a variant pattern. Independent verification caught this. See skill `verified-cron-bugfix`.
