## Graph Engineering (Anthropic-Inspired) vs Our GraphWork System

**Source**: Anthropic engineers paper (Jul 2026), summarized by @mikenevermiss.
**GitHub**: cobusgreyling/graph-engineering (pip: simple-graph-agents)

### The 6-Step Playbook (from Anthropic paper)
1. Start with Karpathy's loop: generate → critique → revise
2. Give agents tools: search, code execution, databases
3. Run agents in parallel with Git worktrees (same repo, different branches)
4. Connect everything with a graph: structured nodes/edges instead of conversations
5. Ground the evaluator: check claims against graph edges, not intuition
6. Make the graph persistent: survives sessions, agents continue from where they left off

### Key Shift: Loops → Graphs
- Karpathy: one agent thinking better through a loop
- Anthropic: thousands of agents coordinating through a graph
- Same models, completely different architecture

### Their Implementation (simple-graph-agents)
- Zero-dependency, ~400 lines Python
- Fluent API: node/edge/branch/chain + validate()
- Mermaid + ASCII rendering built-in
- Patterns: research→write→verify, tool_router, multi_agent_handoff

### Our GraphWork System (32.GraphEngineeredWork)
- GRAPH.md spec: declarative YAML for DAG (finite) + Loops (infinite)
- graph_scaffold.py: scaffolds projects with GRAPH.md + AGENTS.md + decisions/
- graph_parser.py: validates, renders Mermaid, computes critical path
- Ground truth anchoring: every graph has irreducible reality check
- Loop types: inner (embedded in graph nodes), outer (spawn new graphs)
- Already deployed across 100+ clawd projects

### Comparison
| Dimension | simple-graph-agents | Our GraphWork |
|-----------|-------------------|---------------|
| Scope | Runtime executor | Declarative spec + scaffold + parser |
| Persistence | No (by design) | Yes (files survive sessions) |
| Parallel agents | Git worktrees | delegate_task subagents |
| Verification | branch conditional | Ground truth anchors |
| Tool integration | Function nodes | Hermes tools as node actions |
| Rendering | Mermaid/ASCII/DOT | Mermaid (via parser) |
| Dependencies | Zero | Python stdlib + Hermes |

### What We Already Have (They Don't)
1. **Persistence** — Their step 6 (make graph persistent) is our default
2. **Ground truth anchors** — Their step 5 (ground evaluator) is our spec requirement
3. **Decision logging** — Full audit trail per project (decisions/decision-log.md)
4. **Loop embedding** — Inner loops in graph nodes, outer loops spawn graphs

### What They Have (We Don't)
1. **Runtime execution** — They have a working graph executor; we have spec + parser but no runner
2. **Conditional branching** — Their branch() with path_map enables retry/route patterns at runtime
3. **ASCII rendering** — Quick terminal visualization (minor)
4. **Multi-agent handoff** — Explicit handoff pattern between nodes

### Changes Needed
1. **Add a runtime executor** to GraphWork — a Python runner that reads GRAPH.md and executes nodes
2. **Add conditional branching** — retry/route edges based on node output
3. **Add parallel execution** — fan-out nodes that dispatch to delegate_task subagents
4. **Add RunResult trail** — execution trace showing actual node path taken
5. **Wire autoresearch as a graph** — research→eval→ratchet becomes nodes+edges instead of procedural code

### Connection to autoresearch
The autoresearch skill (propose→eval→ratchet with git keep/revert) IS step 1-2 of their playbook:
- generate (propose) → critique (eval) → revise (ratchet)
But it's procedural, not graph-based. Converting it to a GRAPH.md would:
- Make each step independently inspectable
- Enable parallel research directions as branch nodes
- Add ground-truth anchored verification (currently missing)
- Make the research state persistent across sessions
