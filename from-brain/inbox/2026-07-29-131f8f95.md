## GraphWork Runtime Executor — graph_runner.py

Built and tested the runtime executor for GRAPH.md files, implementing the Anthropic Graph Engineering playbook on top of our existing spec.

### What Was Built
1. **graph_runner.py** (~640 lines) — topological sort, node execution, conditional branching, anchor gates, RunResult trail
2. **autoresearch_actions.py** — propose→research→eval→ratchet as registered graph actions
3. **autoresearch.graph.md** — the autoresearch skill converted to GRAPH.md format
4. **GRAPH_SPEC.md updated** — documented action: field, resolver:, and CLI usage

### Key Design Decisions
- Nodes receive a state dict (structured data, not conversations) — Anthropic step 4
- Decision nodes route at runtime via resolver: callables — conditional branching
- Anchor nodes block execution on failure — ground truth gates (Anthropic step 5)
- RunResult trail is inspectable and persistent — survives sessions (Anthropic step 6)
- ActionRegistry pattern — register Python callables by name, nodes reference them via action: field

### Test Results
- Dry run against blueprint GRAPH.md: ✅ 6 nodes ordered correctly
- Live execution: ✅ propose→research→eval→decision→commit→verify-knowledge
- Commit path (score improved): ✅ anchor passes
- Revert path (score not improved): ✅ anchor fails (nothing new learned)

### Connection to Anthropic Paper
Their 6-step playbook mapped to our system:
- Steps 1-2 (Karpathy loop + tools): already in autoresearch skill
- Step 3 (parallel agents): delegate_task subagents (future: worktree isolation)
- Step 4 (graph, not conversations): NOW implemented via graph_runner
- Step 5 (grounded evaluator): anchors in spec + runner
- Step 6 (persistent graph): files survive sessions (always our default)
