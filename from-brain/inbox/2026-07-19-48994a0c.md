# Hermes Self-Healing Systems

Multiple layers of automated repair exist in the Hermes ecosystem. As of 2026-07-19, they are **diagnostically capable but not yet surgically capable** — they can identify what's broken, but cannot autonomously fix it.

## Layers

### 1. Dojo Auto-Heal (dojo-eval.sh)
- **What it does:** Monitors session DB for tool failures, classifies them, generates fix recommendations
- **Auto-fix capability:** Only `add_prerequisite` (appends real deps). All other actions now honestly report "MANUAL ACTION required"
- **Honesty status:** Fixed 2026-07-19 (was previously emitting fake "Added retry handling note" messages)
- **Known issue:** Circuit breakers never record `last_success` — all 15 half-open forever
- **Detailed audit:** [[2026-07-19-1778aee0]]

### 2. Outer Loop (outer_loop_dojo_eval.py)
- **What it does:** Runs every 15 min, can patch `dojo-eval.sh` itself via text replacement
- **Auto-fix capability:** Wraps analyze call in retry loops. Crude, `bash -n`-only validation
- **Risk:** Can modify the very script that runs it (self-modification without full validation)
- **Status:** Not audited, not modified. Flagged for review.

### 3. Cron Self-Heal (cron-self-healing skill)
- **What it does:** Detects failing cron jobs and applies fixes from skill knowledge
- **Status:** Skill exists but not integrated into the dojo pipeline

## Design Principle

> **An honest diagnostician is better than a dishonest surgeon.**

Fake auto-fixes (comment-only patches that look like fixes) are worse than no auto-fix because they:
1. Create false confidence that issues are resolved
2. Accumulate spam in skill files
3. Mask the real need for human intervention
4. Waste review time chasing phantom fixes

The 2026-07-19 refactor converted all fake patches to honest "MANUAL ACTION required" messages while preserving the diagnostic pipeline (analysis JSON, circuit breaker inputs, recommendations).

## Roadmap

- **Near-term:** Fix circuit breaker `last_success` recording
- **Medium-term:** Audit `outer_loop_dojo_eval.py` self-patching safety
- **Open question:** Whether to implement real auto-fix (actual retry/timeout code injection per skill) or keep the honest-diagnostician design
- **Reusable workflow:** See skill `verified-cron-bugfix` for the audit-first fix methodology
