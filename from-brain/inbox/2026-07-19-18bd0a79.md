# Graph-Engineered Work

A declarative work model unifying **directed graphs** (finite games) with **embedded loops** (infinite games). Projects are DAGs with decision points and exit criteria; habits are loops with cadence and condition. Inner loops embed in graph nodes; outer loops spawn new graphs.

## Core Thesis

Work bifurcates into two structures that have been treated separately but should be unified:

- **Graphs (finite game):** Tasks, decisions, milestones. Has a terminal node. Answers "is this done?"
- **Loops (infinite game):** Habits, rhythms, reviews. No terminal node. Answers "did I show up?"

The insight: **loops embed inside graph nodes** (an inner optimization loop within a task), and **outer loops spawn new graphs** (a weekly review that launches a course-correction project).

## The 6-Layer Model

| Layer | Structure | Game Type | Key Question | Theoretical Source |
|-------|-----------|-----------|--------------|--------------------|
| Projects/deliverables | DAG | Finite | "Is this done?" | Topological sort, critical path |
| Habits/capacity | Loop | Infinite | "Did I show up?" | Duhigg/Eyal/Clear |
| Knowledge/context | Anchor | Ground truth | "Is this real?" | Steinberger/Perez caveat |
| Decision cadence | OODA loop | Both | "Am I cycling fast enough?" | Boyd |
| Meta-review | Double-loop | Infinite | "Are my goals even right?" | Argyris |
| Allocation | Gittins index | Both | "Value + information — which arm now?" | Bandit theory |

**One-line model:** *Run finite DAGs to deliver, run infinite loops to grow, spend a Gittins-indexed slice exploring new arms so tomorrow's loops are better than today's.*

## The Ground Truth Anchor (Critical)

From the Steinberger/Perez discourse (July 2026): even a graph of loops fools itself if every loop reads from the same internal data. You need a **ground truth anchor** — something in the graph that can't be gamed by the loops.

> The honest caveat nobody mentions: even a graph of loops can fool itself if every loop reads from the same internal data. You still need something that anchors to reality.
> — Carlos Perez, "From Loop Engineering to Graph Engineering"

In practice: real code execution, SHA256 verification, independent tool output — not self-reported success metrics.

## GRAPH.md Spec (v0.1)

Declarative format using YAML code-fence blocks within markdown.

### Node Types
- `task` — finite work unit (has exit_criteria)
- `decision` — branch point (has decides list)
- `milestone` — exit gate (has exit_criteria, marks phase done)
- `anchor` — ground truth verifier (has ground_truth field, can't be faked)
- `loop` — embedded infinite rhythm (has cadence + condition)

### Edge Types
- `depends_on` — DAG dependency (checked for cycles)
- `decides` — decision branch (NOT cycle-checked)
- `resolution` — chosen branch of resolved decision
- `loops_to` — intentional cycle (NOT cycle-checked)

### Outer Loop Types
- `single-loop` — optimize within current model
- `double-loop` — question the model itself (Argyris)
- `ooda` — observe-orient-decide-act (Boyd)
- `gittins` — exploration vs exploitation (bandit theory)

## Key Distinction: Cycle Checking

Only `depends_on` edges are checked for cycles — this is the mathematical embodiment of the finite/infinite distinction. `loops_to` edges are intentionally cyclic; loops ARE cycles. A "project" with a cycle in its DAG has confused a loop with a DAG.

## Discourse Context (July 2026)

Peter Steinberger's viral tweet ("Are we still talking loops or did we shift to graphs yet?") sparked the transition. Carlos Perez's article "From Loop Engineering to Graph Engineering" operationalized it: build a **graph of loops** — faster optimizer loops, slower watchdog loops, counter-metrics, and a ground truth anchor.

This work goes further by connecting it to finite/infinite game theory (Carse/Sinek) and adding the Gittins allocation layer.
