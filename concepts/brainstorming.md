# Brainstorming

> Design-first conversation before writing any code. Turns rough ideas into fully-formed designs through collaborative dialogue. One question at a time — explores project context, refines requirements, proposes 2-3 approaches with trade-offs, presents design for user approval, writes design doc. Ported from Obra Superpowers methodology.

## Overview

- **Core Principle** — Design through conversation before writing code. Refine ideas through questions, explore alternatives, present designs in sections for validation, and get explicit user approval before any implementation.
- **Anti-Pattern: "This Is Too Simple To Need A Design"** — Every project goes through this process. A todo list, a single-function utility, a config change — all of them. "Simple" projects are where unexamined assumptions cause the most wasted work. The design can be short (a few sentences for truly simple projects), but you MUST present it and get approval.
