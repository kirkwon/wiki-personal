# Skill From Masters

> Practice-first research layer that runs BEFORE skill-creator. Find top practitioners (not theorists), extract how they do it via golden/failure cases, build contrast tables, then hand off to skill-creator. Use whenever creating a new skill for a domain where masters exist, or when a skill needs grounding in real expert practice.

## Overview

- **When to Use** — - Creating a new skill for a domain where expert practitioners exist - Improving a skill that feels "academic" or theory-heavy - Any time `skill-creator` would be invoked, run this first as the research layer - User says "build me a skill for X" and X is a human domain (sales, writing, investing, debugging, etc.)
- **When NOT to Use** — - Pure code/utility tasks with no human expertise dimension (format conversions, cron jobs) - Skills being extracted from a single methodology document (use `skill-from-exemplar` Path A instead) - When `search-skill` can find an existing skill that already solves the problem
- **Core Principle: Practice-First, Not Theory-First** — | Practical Expert (Doer) | Theoretical Expert (Writer) | |--------------------------|-----------------------------| | The #1 salesperson | Sales methodology author | | The interviewer who actually hires great people | Interviewing book author | | The dev who ships clean code fast | Clean code book author |

## Further detail

### The Skill Quality Test

> *"Does this skill feel like someone who's done this a thousand times, or someone who's read a lot of books about it?"*

### Output Format

The research layer produces a **case brief** that feeds into skill-creator:
